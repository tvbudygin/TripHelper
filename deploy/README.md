# Docker и GitHub Actions

## Что запускается
На сервере работают контейнеры приложения (FastAPI + собранный React), PostgreSQL и Nginx.
Certbot запускается отдельно для сертификатов. Наружу открыты только 80 и 443, а также SSH сервера.
База, документы и сертификаты находятся в именованных томах, обновление приложения их не удаляет.
Время приложения - Москва. Сборка выполняется на GitHub для Linux amd64, сервер нужен x86_64.

## Локально
В корне проекта: `docker compose up -d --build`. Сайт: http://localhost:8000.
Порт PostgreSQL: 127.0.0.1:5433. В .env можно положить ключи API и SMTP.
Новая конфигурация использует собственные тома Compose. Существующие контейнеры и их данные
автоматически не переносятся: перед переходом нужно сделать экспорт и импорт базы.
Если порт уже занят старым TripHelper, сначала остановите именно старое приложение.

## Первый запуск на новом сервере
1. Установить Docker Engine и Compose plugin по https://docs.docker.com/engine/install/ubuntu/
2. Создать пользователя для выкладки, дать ему доступ к Docker и право записи в /opt/triphelper.
   Доступ к Docker даёт широкие права на сервере, SSH-ключ использовать отдельный.
3. Скопировать deploy/.env.example в /opt/triphelper/.env, права 600.
   Заполнить POSTGRES_PASSWORD, SECRET_KEY, FRONTEND_BASE_URL, ключи API и SMTP.
   Для пароля БД и SECRET_KEY можно дважды выполнить `openssl rand -hex 32`.
   Пароль БД должен содержать только буквы и цифры, так как входит в URL подключения.
   APP_IMAGE обновит скрипт выкладки. Локальный .env на сервер не отправляется.
4. Создать отдельный SSH-ключ. Публичную часть добавить в authorized_keys пользователя выкладки.
5. В репозитории GitHub: Settings → Secrets and variables → Actions добавить secret
   DEPLOY_SSH_KEY (приватная часть отдельного ключа ~/.ssh/triphelper_ci).
   Публичная часть уже установлена для пользователя deploy на 185.175.226.33.
   Адрес, пользователь и порт по умолчанию заданы в workflow. При переезде их можно
   переопределить Actions variables DEPLOY_HOST, DEPLOY_USER, DEPLOY_PORT.
   Проверенный публичный ключ сервера сохранён в deploy/known_hosts.
   При смене сервера этот файл нужно обновить после сверки отпечатка.
6. Добавить Actions variable DEPLOY_ENABLED со значением true.
   Пока переменной нет, выполняются только сборка и проверки.
7. Сделать commit и push в main. Actions соберёт образ, проверит с отдельной БД,
   передаст образ по SSH и запустит контейнеры. Можно запустить workflow вручную из main.
8. Для переноса старых данных отдельно импортировать дамп PostgreSQL и файлы uploads.
   Не переносить каталог данных PostgreSQL между произвольными версиями.

## HTTPS
У домена должна быть A-запись на IP нового сервера. AAAA нужна только при настроенном IPv6.
После первой выкладки выполнить на сервере:
```sh
bash /opt/triphelper/enable-https.sh example.com admin@example.com
```
Указать свой домен и почту. В .env FRONTEND_BASE_URL должен быть https://ваш-домен.
Скрипт получает сертификат Let's Encrypt и включает редирект с HTTP на HTTPS.
Для автоматического продления добавить в crontab пользователя с доступом к Docker:
```cron
17 3 * * * bash /opt/triphelper/renew-cert.sh >> /opt/triphelper/cert-renew.log 2>&1
```
Порты 80 и 443 должны оставаться доступными.

## Обновления и данные
Каждый push в main запускает проверки и, при DEPLOY_ENABLED=true, выкладку.
Перед обновлением существующей БД сохраняется дамп в /opt/triphelper/backups.
Для постоянного резервного копирования нужны отдельное расписание и копии вне сервера,
включая uploads. Следить за размером backups, Docker-образов и свободным местом.
Не выполнять `docker compose down -v` на сервере: эта команда удаляет данные.

create_all создаёт новые таблицы, но не меняет существующие столбцы.
Изменения структуры существующей БД требуют отдельной миграции перед выкладкой.
Текущий CI проверяет запуск с новой PostgreSQL, а не миграцию старых данных.

Автоматического отката нет. При неудаче workflow сообщает ошибку.
Чтобы вернуть прежний код, поставить в серверном .env APP_IMAGE=triphelper:ПРЕДЫДУЩИЙ_SHA,
затем из /opt/triphelper выполнить:
```sh
docker compose -f compose.yml up -d --wait app
docker compose -f compose.yml up -d --force-recreate nginx
```
Предыдущий образ нужно сохранять на сервере. Откат образа не откатывает структуру БД.

Коммиты, push, настройка GitHub secrets и первое подключение сервера выполняются отдельно.
