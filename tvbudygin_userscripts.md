### [ Сценарий 1 — Регистрация и вход в систему ]

1. Пользователь открывает сайт TripHelper и нажимает кнопку регистрации.
2. Пользователь вводит имя, электронную почту и пароль.
3. Система проверяет корректность введённых данных.
4. Если почта уже зарегистрирована, система сообщает об ошибке и предлагает войти в аккаунт.
5. Если пароль не соответствует требованиям безопасности, система выводит предупреждение.
6. После успешной регистрации пользователю отправляется письмо для подтверждения электронной почты.
7. Пользователь подтверждает регистрацию через ссылку в письме.
8. Система создаёт аккаунт пользователя и автоматически выполняет вход.
9. Пользователь попадает на главную страницу сервиса.
10. При последующих посещениях пользователь может войти по почте и паролю.


### [ Сценарий 2 — Создание новой поездки ]

1. Пользователь нажимает кнопку «Создать поездку».
2. Пользователь вводит название поездки.
3. Пользователь указывает страну, город и даты путешествия.
4. Пользователь может добавить описание или заметки.
5. Система создаёт новую карточку поездки.
6. После создания поездка отображается на главной странице пользователя.
7. Пользователь может открыть поездку для дальнейшего редактирования.
8. Если даты введены некорректно, система сообщает об ошибке.
9. Пользователь может позже изменить параметры поездки.
10. После сохранения поездка становится доступна для добавления других элементов путешествия.


### [ Сценарий 3 — Добавление способа передвижения ]

1. Пользователь открывает страницу поездки.
2. Пользователь нажимает кнопку «Добавить перемещение».
3. Система предлагает выбрать тип транспорта: самолёт, поезд, автобус, автомобиль, паром или другое.
4. Пользователь вводит точки отправления и прибытия.
5. Пользователь указывает дату и время поездки.
6. Пользователь может загрузить билет или подтверждение бронирования в формате PDF или изображения.
7. Система пытается автоматически распознать данные из документа.
8. Если распознавание прошло успешно, часть полей заполняется автоматически.
9. Пользователь проверяет информацию и при необходимости редактирует её вручную.
10. После сохранения способ передвижения отображается в общей структуре путешествия и временной линии поездки.


### [ Сценарий 4 — Добавление жилья ]

1. Пользователь открывает нужную поездку.
2. Пользователь выбирает раздел «Жильё».
3. Пользователь нажимает кнопку добавления места проживания.
4. Пользователь вводит название отеля, апартаментов, хостела или другого жилья.
5. Пользователь указывает даты заселения и выезда.
6. Пользователь может добавить адрес, стоимость проживания и комментарии.
7. Дополнительно можно загрузить подтверждение бронирования.
8. После сохранения жильё отображается в структуре поездки.
9. Если даты проживания выходят за пределы поездки, система выводит предупреждение.
10. Пользователь может изменить или удалить данные о жилье позже.


### [ Сценарий 5 — Добавление активности или места посещения ]

1. Пользователь открывает страницу поездки.
2. Пользователь выбирает раздел «Активности».
3. Пользователь нажимает кнопку «Добавить активность».
4. Пользователь указывает тип активности: музей, экскурсия, концерт, ресторан, парк, выставка или другое.
5. Пользователь вводит название места и дату посещения.
6. Пользователь может добавить время, адрес, стоимость и заметки.
7. При необходимости пользователь загружает билет или подтверждение бронирования.
8. После сохранения активность отображается внутри поездки.
9. Система автоматически добавляет место в статистику посещённых объектов.
10. Пользователь может редактировать или удалять активность в любой момент.


### [ Сценарий 6 — Получение уведомлений и обновлений ]

1. Пользователь добавляет данные о поездке в систему.
2. Сервис сохраняет информацию о датах, времени и перемещениях.
3. Система отслеживает изменения статусов рейсов и других событий поездки.
4. Если происходит изменение или приближается важное событие, система формирует уведомление.
5. Пользователь получает уведомление внутри сервиса.
6. Дополнительно уведомление может быть отправлено на электронную почту.
7. Пользователь открывает уведомление и просматривает обновлённую информацию.
8. Если данные были изменены повторно, система автоматически обновляет информацию.
9. Пользователь может включать или отключать уведомления в настройках.
10. История уведомлений сохраняется внутри аккаунта пользователя.


### [ Сценарий 7 — Работа с AI-помощником ]

1. Пользователь открывает встроенный AI-чат.
2. Пользователь задаёт вопрос, связанный с поездкой.
3. Система анализирует запрос пользователя.
4. Классификатор определяет тип запроса.
5. AI-модуль получает необходимые данные о поездке.
6. Система формирует ответ с учётом информации пользователя.
7. Пользователь получает ответ в окне чата.
8. Если AI не может дать точный ответ, система сообщает об ограничении.
9. Пользователь может продолжить диалог или задать новый вопрос.
10. История сообщений сохраняется внутри аккаунта.


### [ Сценарий 8 — Просмотр статистики путешествий ]

1. Пользователь открывает раздел статистики.
2. Система загружает данные обо всех поездках пользователя.
3. Пользователь видит количество посещённых стран и городов.
4. Система отображает информацию о посещённых местах и активностях.
5. Пользователь может просматривать список поездок за разные периоды времени.
6. Система показывает общую статистику перемещений и путешествий.
7. Пользователь может фильтровать статистику по годам или странам.
8. При добавлении новых поездок статистика обновляется автоматически.
9. Пользователь может открыть конкретную поездку из статистики.
10. Все данные сохраняются в профиле пользователя.
