**[ НАЗВАНИЕ ПРОЕКТА ]**

"TripHelper – Сервис, помощник путешественникам"

**[ ПРОБЛЕМНОЕ ПОЛЕ ]**

Во время путешествий информация хранится в разных приложениях: билеты отдельно, жильё отдельно, планы отдельно. Из-за этого легко запутаться и забыть важные детали. TripHelper собирает всё в одном месте, присылает напоминания, сообщает об изменениях рейсов и позволяет быстро получать нужные данные через AI-бота.

**[ ЗАКАЗЧИК / ПОТЕНЦИАЛЬНАЯ АУДИТОРИЯ ]**

Продукт ориентирован на путешественников, которым необходимо удобно управлять поездками и хранить всю информацию в одном месте. Основные группы пользователей:
* Люди, которые регулярно путешествуют и бронируют перелёты
* Пользователи, организующие поездки с несколькими этапами (перелёты, отели, экскурсии)
* Туристы, которым важно получать напоминания и актуальные данные о рейсах
* Путешественники, желающие фиксировать статистику посещённых стран и городов

**[ АППАРАТНЫЕ / ПРОГРАММНЫЕ ТРЕБОВАНИЯ ]**

TripHelper доступен по адресу https://triphelper.site через браузер на ПК и смартфоне. Для работы нужны доступ к интернету, современный браузер Chrome, Firefox, Edge или Safari. Интерфейс подстраивается под ширину экрана.

Текущая серверная конфигурация:

* VPS с Ubuntu 24.04, 2 ГБ оперативной памяти и диском около 30 ГБ
* Python 3.12 и PostgreSQL 16 в контейнерах Docker
* Docker Compose для совместного запуска приложения, базы данных и Nginx
* Nginx принимает HTTPS-запросы на порту 443; порт 80 используется для перенаправления HTTP на HTTPS
* Приложение работает на порту 8000, PostgreSQL на порту 5432 внутри сети Docker
* Исходящие соединения нужны для OpenRouter, Aviationstack и отправки почты через SMTP


**[ ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ ]**

Каждому требованию соответствует сценарий с тем же номером в final_scripts.md.

1. Пользователь может зарегистрироваться, войти по почте и паролю и подтвердить адрес через письмо; не подтверждение почты не блокирует вход
2. Пользователь может создавать, изменять и удалять поездки, указывать даты, страну выезда и несколько стран и городов маршрута
3. Пользователь может добавлять перемещения, даты отправления и прибытия, аэропорты, перевозчика, номер рейса или билета, гейт или платформу, вагон, место, стоимость и документ; данные документа можно распознать и исправить вручную
4. Пользователь может добавлять жильё, даты и время заселения и выезда, адрес, стоимость и документ бронирования с распознаванием данных
5. Пользователь может добавлять активности, дату и время посещения, часы открытия и закрытия, адрес, стоимость и документ с распознаванием данных
6. Пользователь может получать напоминания о поездках и отправлениях на сайте и по почте, просматривать, читать и удалять уведомления, управлять их получением в профиле
7. Пользователь может задавать AI-помощнику вопросы о сохранённых поездках и получать общие рекомендации о местах и еде с сохранением истории диалога
8. Пользователь может просматривать в профиле общие счётчики поездок, стран, городов, жилья, активностей и перемещений, карту стран маршрутов и список поездок с фильтрами по году и стране
9. Пользователь может по кнопке запросить статус авиарейса через Aviationstack и увидеть обновлённый статус и время отправления при наличии данных
10. Пользователь может видеть сумму расходов на перемещения, жильё и активности, добавлять и удалять прочие расходы в бюджете поездки
11. Пользователь может скачать общий файл .ics с событиями всех своих поездок для импорта в календарное приложение
12. Пользователь может завершить поездку вручную или получить автоматическое завершение после даты ее окончания, а затем, если нужно, то вернуть поездку из завершённых

**[ ПОХОЖИЕ / АНАЛОГИЧНЫЕ ПРОДУКТЫ ]**

Анализ похожих сервисов показывает, что:

* Приложения авиакомпаний показывают только информацию о перелётах, но не помогают хранить данные о жилье и экскурсиях.
* Сервисы вроде Booking содержат только бронирования отелей.
* Планировщики путешествий обычно не имеют AI-помощника и не сообщают автоматически о задержках или отменах рейсов.
* Большинство существующих решений не собирают все этапы поездки в одном удобном месте.

TripHelper решает эту проблему: он объединяет билеты, жильё, планы и напоминания в одном сервисе и добавляет AI-бота для быстрых подсказок.

**[ ИНСТРУМЕНТЫ РАЗРАБОТКИ, ИНФОРМАЦИЯ О БД ]**

* Backend: Python 3.12, FastAPI, Uvicorn, SQLAlchemy
* Frontend: React, Vite, JavaScript и CSS
* База данных: PostgreSQL 16; хранит пользователей, поездки, перемещения, жильё, активности, расходы, уведомления и сообщения чата
* Развёртывание: Docker Compose, Nginx и HTTPS
* Контроль версий и обновление сервера: Git, GitHub и GitHub Actions
* AI-запросы: OpenRouter; извлечение текста и подготовка изображений PDF: pypdf и PyMuPDF
* Статусы авиарейсов: Aviationstack
* Почта: SMTP для подтверждения адреса и копий уведомлений

AI-чат состоит из классификатора запросов, основного агента и валидатора ответов.

Классификатор разделяет вопросы на четыре категории:
* `trip_info` - вопросы о своих поездках
* `recommendation` - рекомендации для путешествия
* `stats` - вопросы об общей статистике; система направляет человека в профиль, где ведется статистика
* `off_topic` - вопросы, не связанные с путешествиями; система сообщает, что помощник отвечает только на вопросы о путешествиях

Сначала классификатор проверяет ключевые слова. Если по ним не удалось определить категорию, он обращается к модели через OpenRouter с учётом истории диалога. Если модель не ответила или вернула неизвестную категорию, используется `trip_info`. 

Валидатор проверяет ответ агента. Он должен исправлять противоречия данным поездки и заменять точные цены, часы работы и телефоны предложением уточнить их перед визитом. Обычные рекомендации достопримечательностей, районов, блюд и известных заведений сохраняются. Если исправления не нужны, ответ возвращается без изменений.
Дополнительно проверяется не выдал ли бот технические ошибки: непонятный текст, не на русском, служебные ответы и т д

Данные из документов извлекаются с помощью ИИ через OpenRouter и подставляются в форму для проверки пользователем. Здесь нет классификатора и валидатора чата. Из PDF извлекается текст, а текста мало то, первая страница преобразуется в изображение. Фотография передаётся модели как изображение. Модель возвращает найденные поля документа, которые пользователь может исправить перед сохранением.

Статус рейса запрашивается по кнопке, постоянного фонового опроса авиа-API нет(т. к. кол-во запрос ограничено). Проверка использует номер рейса и дату, время. Если подходящих данных нет, сервис сообщает об этом.

Статистика включает все сохранённые поездки, в том числе запланированные. Карта учитывает страну выезда, основную страну и дополнительные страны маршрута. Стоимости суммируются без пересчёта валют. Файл календаря можно скачать и добавить в свой календарь.

**[ ВОЗМОЖНЫЕ РИСКИ ]**

* Ошибки в ответах AI-бота: внедрение строгой валидации и ограничений
* Сложности с подключением внешних API: тестирование разных API и подбор наиболее стабильных
* Высокая стоимость LLM API: использование бесплатных или open-source моделей, оптимизация числа запросов, кеширование ответов, ограничение AI-функций только действительно важными сценариями.
* Плохое качество парсинга изображений и PDF: предварительная обработка файлов, возможность ручного ввода данных пользователем при ошибках распознавания, применение специализированных OCR-инструментов.
